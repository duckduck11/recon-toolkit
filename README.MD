# Recon Pipeline

Automated domain and subdomain discovery pipeline based on **ProjectDiscovery** tools.

The project is designed to enumerate domains and subdomains, verify DNS resolution, detect active HTTP/HTTPS services and generate a consolidated CSV inventory that can be used for security assessments, attack surface management and infrastructure audits.

---

# Features

* Passive subdomain enumeration using **subfinder**
* DNS verification using **dnsx**
* HTTP/HTTPS fingerprinting using **httpx**
* Automatic deduplication
* Stage caching (no unnecessary rescans)
* Resume-friendly workflow
* Single CSV report containing all collected information

---

# Workflow

```text
             domains.txt
                  │
                  ▼
          Input normalization
                  │
                  ▼
         root_domains.txt
                  │
                  ▼
             subfinder
                  │
                  ▼
          subfinder.txt
                  │
                  ▼
             Merge hosts
                  │
                  ▼
          all_hosts.txt
                  │
                  ▼
                dnsx
                  │
        ┌─────────┴─────────┐
        │                   │
        ▼                   ▼
    dnsx.jsonl         alive.txt
                              │
                              ▼
                            httpx
                              │
                              ▼
                         httpx.jsonl
                              │
                              ▼
                         report.csv
```

# Requirements

## Operating System

* Linux (recommended: Kali Linux)

## Python

Python 3.10 or newer.

## Required tools

The following ProjectDiscovery tools must be installed and available in your `PATH`:

* subfinder
* dnsx
* httpx

Verify installation:

```bash
which subfinder
which dnsx
which httpx
```

---

# Input file

The input file must contain **one domain or hostname per line**.

Example:

```text
example.com
example.org
company.net
```

The input may also contain:

```text
example.com
www.example.com
vpn.example.com
mail.example.com
```

Duplicates are removed automatically.

---

# Usage

Basic usage:

```bash
python3 recon.py domains.txt
```

Specify an output report:

```bash
python3 recon.py domains.txt -o report.csv
```

---

# Cache mechanism

The pipeline stores intermediate results inside the `work/` directory.

If a stage has already been completed, it is skipped automatically.

Example:

```text
[+] subfinder.txt exists - skipping
[+] dnsx.jsonl exists - skipping
```

This makes it possible to:

* resume interrupted scans
* avoid repeating expensive enumeration
* regenerate reports without running the entire pipeline again

---

# Intermediate files

## root_domains.txt

List of root domains used by **subfinder**.

---

## input_hosts.txt

Original user input.

---

## subfinder.txt

Subdomains discovered by **subfinder**.

Example:

```text
vpn.example.com
mail.example.com
api.example.com
```

---

## all_hosts.txt

Combined list of:

* input hosts
* subfinder results

Duplicates are removed automatically.

---

## dnsx.jsonl

Raw JSON output generated by **dnsx**.

Contains information such as:

* host
* A records
* AAAA records
* CNAME records

---

## alive.txt

Hosts successfully resolved by DNS.

These hosts are passed to **httpx**.

---

## httpx.jsonl

Raw JSON output generated by **httpx**.

Contains HTTP fingerprinting information including:

* status code
* page title
* redirect target
* technologies
* web server
* CDN
* favicon hash

---

# CSV Report

The primary output of the pipeline is:

```text
work/report.csv
```

Each row represents one domain or subdomain.

## CSV columns

| Column         | Description                                  |
| -------------- | -------------------------------------------- |
| domain         | Domain or hostname                           |
| type           | Asset type (reserved for future use)         |
| source         | Source of discovery (input, subfinder, etc.) |
| dns            | DNS resolution successful                    |
| ip             | IPv4 addresses                               |
| cname          | CNAME records                                |
| http           | HTTP service detected                        |
| https          | HTTPS service detected                       |
| status_code    | HTTP response status                         |
| title          | HTML page title                              |
| redirect       | Redirect detected                            |
| redirect_to    | Redirect destination                         |
| server         | Web server fingerprint                       |
| tech           | Detected technologies                        |
| archive        | Reserved for future archive integration      |
| content_length | HTTP response size                           |
| cdn            | Detected CDN                                 |
| favicon_hash   | Favicon hash                                 |

# Result interpretation

## Active web application

```text
dns = True
https = True
status_code = 200
```

The host exists and serves a web application.

---

## DNS only

```text
dns = True
http = False
https = False
```

The hostname resolves successfully but no HTTP service is available.

Possible examples:

* VPN
* SMTP server
* API endpoint
* internal service
* abandoned DNS record

---

## Redirect

```text
status_code = 301
redirect = True
redirect_to = https://example.com
```

The host redirects users to another location.
